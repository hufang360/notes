## 为啥是docker

mac上怎么开服！昨天我已经摸索出来了，我们启动的饥荒就自带开服工具。写个启动脚本就可以了，但还是想折腾一下docker，往后如果要在linux上跑，也能光速开服。

mac原版开服大致流程：

```bash
# 先用饥荒创建世界
# 自定义好世界，配好mod

# 找到世界文件，将 Cluster_1 文件夹复制到上一级目录
# 其中 132274880 可能是用户id什么的，每个人可能不相同
mv $HOME/Documents/Klei/DoNotStarveTogether/132274880/Cluster_1 \
   $HOME/Documents/Klei/DoNotStarveTogether/Cluster_1
# cd "$HOME/Documents/Klei/DoNotStarveTogether"
# mv [0-9]*/Cluster_1 .

# 申请令牌
# https://accounts.klei.com/account/game/servers?game=DontStarveTogether
# 将令牌写入
# $HOME/Documents/Klei/DoNotStarveTogether/Cluster_1/cluster_token.txt

# 编写启动脚本
# runDST.sh
```

```bash
#!/bin/bash

# 切换工作目录
cd "$(dirname "$0")"|| exit

# install_dir="$HOME/Library/Application Support/Steam/steamapps/common/Don't Starve Together Dedicated Server/dontstarve_dedicated_server_nullrenderer.app"
install_dir="$HOME/Library/Application Support/Steam/steamapps/common/Don't Starve Together/dontstarve_steam.app"
doc_dir="$HOME/Documents/Klei"
cluster_name="Cluster_1"

cd "$install_dir/Contents/MacOS" || exit

run_shared=(./dontstarve_dedicated_server_nullrenderer)
run_shared+=(-console)
run_shared+=(-cluster "$cluster_name")
run_shared+=(-monitor_parent_process $$)
run_shared+=(-persistent_storage_root "$doc_dir" )

#不想开启洞穴就把&和后面的都去掉
"${run_shared[@]}" -shard Master | sed 's/^/Master: /' &
"${run_shared[@]}" -shard Caves  | sed 's/^/Caves:  /'
```

## DepotDownloader

除steamcmd外，还可以用DepotDownloader来下载steam上的游戏，而且饥荒开服工具可以匿名下载，不需要登录steam账号。

看到一个受欢迎的镜像，但是长时间没更新，于是在ai的帮助下我打了一个docker。基于.net9.0，镜像有支持 `linux/arm64`，能在我的macmini上运行，大概 77MB，pull到本地大概占 200mb。

至此，get到了，最新版的饥荒开服工具~后续更新开服工具也是这么操作~

https://github.com/SteamRE/DepotDownloader

https://hub.docker.com/r/hufang360/depotdownloader

```bash
SVR=data/dst_server          # 服务端程序存放目录

# 起过容器后，上游 entrypoint 会把 mods 换成指向 /data 的软链，
# 那样下载会写不进去，所以先删掉这个软链
[ -L "$SVR/mods" ] && rm -f "$SVR/mods"

# 用 Docker 跑 DepotDownloader，把服务端下载到 $SVR
docker run --rm \
    -v "$PWD/$SVR:/steam" \
    hufang360/depotdownloader \
    -app 343050 -os linux -osarch 64 -branch public -dir /steam -validate

# 给主程序加上可执行权限（DepotDownloader 不会自动加）
chmod +x "$SVR/bin64/dontstarve_dedicated_server_nullrenderer_x64"
```

## 开服令牌

申请令牌请访问 https://accounts.klei.com/account/game/servers?game=DontStarveTogether

得到 `pds-g^`开头的文字令牌，将它写入到 `cluster_token.txt`

```bash
# 引导填写 cluster_token
```

## 基础镜像

继续使用那个最受欢迎的镜像。

由于饥荒开服工具，我们已经有办法下载/更新了。所以这次我们选择，体积最小的 `latest-slim`（里面也有 `/opt/dst_default_config/`）。

```bash
SVR=data/dst_server
CFG=data/dst_default_config
NAME=dst

docker run -d --name "$NAME" \
    --platform "linux/amd64" \
    -e "DST_SERVER_ARCH=amd64" \
    -e "STEAMCMD_PATH=/bin/true" \
    -v "$PWD/$SVR:/opt/dst_server" \
    -v "$PWD/$CFG:/data" \
    -p 10999-11000:10999-11000/udp \
    -p 12346-12347:12346-12347/udp \
    jamesits/dst-server:latest-slim
```

```bash
# 参数解释，这3个参数是必须的
--platform "linux/amd64"， 镜像没有linux/arm64版本，不指定在arm上可能运行失败
-e "DST_SERVER_ARCH=amd64"， 必须，指定开服工具架构
-e "STEAMCMD_PATH=/bin/true"， 禁用steamcmd
```

## 完全体

```bash
#!/bin/bash
# =====================================================================
# DST（饥荒联机版）专用服务器部署脚本
# 顺序：下载 → 拷贝默认配置 → 填 token → 启动
# =====================================================================

cd "$(dirname "$0")"

SVR=data/dst_server
CFG=data/dst_default_config
NAME=dst


# ---------------------------------------------------------------------
# 1. 下载 / 更新服务端
# ---------------------------------------------------------------------
echo "==> [1/4] 下载服务端..."

# 起过容器后，上游 entrypoint 会把 mods 换成指向 /data 的软链，
# 那样下载会写不进去，所以先删掉这个软链
[ -L "$SVR/mods" ] && rm -f "$SVR/mods"

docker run --rm --platform linux/amd64 \
    -v "$PWD/$SVR:/steam" \
    hufang360/depotdownloader \
    -app 343050 -os linux -osarch 64 -branch public -dir /steam -validate

chmod +x "$SVR/bin64/dontstarve_dedicated_server_nullrenderer_x64"

# ---------------------------------------------------------------------
# 2. 生成默认配置（只拷一次）
# ---------------------------------------------------------------------
echo "==> [2/4] 拷贝默认配置..."

# 从镜像里拷贝出默认配置
cid=$(docker create --platform linux/amd64 jamesits/dst-server:latest-slim)
mkdir -p "$CFG"
docker cp "$cid:/opt/dst_default_config/." "$CFG/"
docker rm "$cid" >/dev/null
echo "    默认配置已拷出"



# ---------------------------------------------------------------------
# 3. 检查 / 引导填写 cluster_token
# ---------------------------------------------------------------------
echo "==> [3/4] 写入 cluster_token..."
echo "    申请令牌 https://accounts.klei.com/account/game/servers?game=DontStarveTogether"
echo "    然后粘贴到下面这行："

TOKEN_FILE="$CFG/DoNotStarveTogether/Cluster_1/cluster_token.txt"
read -rp "    token: " USER_TOKEN
printf '%s\n' "$USER_TOKEN" > "$TOKEN_FILE"
echo "    ✅ token 已写入"


# ---------------------------------------------------------------------
# 4. 启动容器
# ---------------------------------------------------------------------
echo "==> [4/4] 启动容器..."

# 删除旧容器
docker rm -f "$NAME" >/dev/null 2>&1

docker run -d --name "$NAME" \
    --platform "linux/amd64" \
    -e "DST_SERVER_ARCH=amd64" \
    -e "STEAMCMD_PATH=/bin/true" \
    -v "$PWD/$SVR:/opt/dst_server" \
    -v "$PWD/$CFG:/data" \
    -p 10999-11000:10999-11000/udp \
    -p 12346-12347:12346-12347/udp \
    jamesits/dst-server:latest-slim

echo "==> 起来了，看日志： docker logs -f $NAME"
```

## 常见问题

问：终端侧的控制台 是否可用？

答：这个方案（supervisord 托管）里 docker attach 只能看日志，不能当控制台用。推荐做法：用游戏内控制台。

```bash
# 把自己设成管理员
vim data/server/DoNotStarveTogether/Cluster_1/adminlist.txt

# 写入你的 Klei 用户 ID（形如 KU_xxxxxxxx）
# 怎么查：进游戏后按 ~ 打开客户端控制台，输入
print(ThePlayer.userid)

# 重启容器
docker restart dst

# 测试
# 进游戏后按 ~ 打开控制台，按一下 Ctrl 切到远程命令模式
c_listallplayers()

# 满状态，可同时复制粘贴这3行
c_sethunger(1)
c_setsanity(1)
c_sethealth(1)
```

问：后面饥荒更新了怎么办？

答：重新执行 DepotDownloader 那步操作，不过mod要重下了，建议在执行前先复制，检查通过后再恢复。

问：性能怎么样？

答：你玩过饥荒么！

docker版开服，orb-stack看占用，单人进服后内存在2.5g左右，cpu在50%左右。

mac原版开服，单人进服后内存在2.26g左右，cpu在40%左右。

mac上，两种方式的差距不大，docker引擎本身也是有一点消耗的，还是原版要省一点，照理跑的开服工具是amd64版，arm上运行效率要低一些。

问：为什么不用actions自动化打docker

答：有人这么干过，比如jamesits，后面怎么没更新了，你细品~

个人觉得科雷应该优化下开服工具的文件大小，开服嘛，那些图片、声音、字体资源就不要了嘛~可能最后就300,500mb就搞定了。小一点，大幅度减少actions的打包时长（额度）~
